# Result Template

Adapt this structure to the size of the project. Omit empty sections, but always preserve priorities, evidence, verification, and limitations.

## Outcome

State what improved, what remains blocked, and whether live verification occurred.

## Changes made

| Area | Change | Files/routes | Reason |
|---|---|---|---|

## Audit findings

| Priority | Finding | Evidence | Resolution/status |
|---|---|---|---|

Use only `Critical`, `High`, `Medium`, or `Low`. Do not provide a numeric score.

## Official-source checks

| Platform | Official source | Accessed | Implementation consequence |
|---|---|---|---|

Separate confirmed rules from inference. Link directly to official pages.

## AI question map and visibility baseline

| Query group | Exact representative question | Platform/market | Before | After/current | Evidence status |
|---|---|---|---|---|---|

Use directly observed platform answers only. If unavailable, provide the repeatable query set and label live AI visibility `Unavailable`.

## Verification

| Check | Command/method | Result |
|---|---|---|

List failures and unrun checks plainly. Never hide them behind a general success statement.

## External visibility plan

| Priority | Target/source type | Value offered | Next action | Success evidence |
|---|---|---|---|---|

Keep this ethical, relevant, and specific to the business. It is a plan unless separate authorization exists for external actions.

## Measurement plan

| Layer | Metric/event | Baseline | Implementation/collection | Cadence | Success evidence |
|---|---|---|---|---|---|

Keep rank, mention, citation, referral, branded demand, and conversion distinct. Record platform, query set, market, date, repetitions, and collection method.

## Post-deployment checklist

- Verify the production hostname, redirects, status codes, canonical URLs, and metadata.
- Fetch production robots and sitemap endpoints.
- Check intended crawler access against current official documentation and deployed WAF/CDN rules.
- Inspect generated and rendered HTML on representative routes.
- Validate deployed structured data against visible content.
- Submit or refresh supported webmaster/platform tools when applicable.
- Monitor crawl logs, index coverage, citations/referrals, and conversion quality over time.

## Limitations

State missing URLs, unavailable tools, unverified business facts, blocked official sources, or deployment-only checks. End with the reminder that eligibility and clarity do not guarantee indexing, ranking, recommendation, or citation.
